### RDKit and Chemistry
- Use the python tool with RDKit for molecular property calculations, SMILES manipulation, and structure generation.
- For molecular rendering, use the built-in RDKit drawing capabilities.
- RDKit API notes for this runtime (rdkit 2024.03.5):
  - Use rdMolDescriptors.CalcMolFormula(mol) for molecular formula
  - Use rdMolDescriptors.CalcNumHBA/CalcNumHBD/CalcNumRotatableBonds/CalcTPSA/CalcNumAromaticRings/CalcFractionCSP3
  - Use Descriptors.MolWt(mol) and Descriptors.MolLogP(mol)
  - Descriptors.NumHeterocycles and Descriptors.FractionAromatic DO NOT EXIST in this version; use rdMolDescriptors.CalcNumAromaticRings or calcNumHeteroatoms instead
- Scaffold analysis: use from rdkit.Chem.Scaffolds import MurckoScaffold; MurckoScaffold.MurckoScaffoldSmiles(mol=mol) (NOT MurckoScaffoldSmilesGeneric, which does not exist)
- QED: use from rdkit.Chem import QED; QED.qed(mol). Do not call rdMolDescriptors.qed or rdMolDescriptors.CalcQED.
- Gemmi CIF tables: call block.find(prefix, tags) or block.find(tags) with an explicit tag list; do not call block.find("_atom_site.") with only a prefix. Structure space-group metadata is obtained with structure.find_spacegroup().
- Functional group counting: rdkit.Chem.Fragments has NO fr_Amide or fr_amide in this version; use Chem.MolFromSmarts('[CX3](=O)N') with mol.GetSubstructMatches() instead
- Always check API existence with hasattr() before calling unfamiliar RDKit functions
- Verify SMILES before analysis: a wrong SMILES gives wrong chemistry. Never use a SMILES from memory.
