# Visual direction and real screenshots

Concept illustrations communicate design intent. Screenshots of the workbench,
running tasks, and scientific results must be captured from the actual product.
AI-generated interface images must not be presented as real product screens.

No verified runtime screenshot is included on this page. A synthetic UI image
is not a substitute for that evidence.

## Visual direction

- **Evidence is the primary object.** Research briefs, source cards, structure
  views, and run states should read as one connected workspace.
- **Quiet hierarchy.** Use a calm graphite shell, warm surfaces, and restrained
  teal/violet accents so scientific content—not decoration—carries attention.
- **State is explicit.** Success, waiting, approval, recovery, and failure need
  distinct status treatments with text equivalents for accessibility.
- **No invented certainty.** Preview imagery must not imply data, metrics, or
  scientific conclusions that the product has not verified.

## Screenshot requirements

- Capture the running application; do not generate or reconstruct its interface.
- Record the source revision, capture date, page, and relevant runtime state.
- Use non-sensitive, consented data. Label demonstration data explicitly.
- Do not synthesize messages, tool outputs, success states, or scientific results.
- Label every concept illustration beside the image, including in translated
  documentation; keep it separate from real application captures.
